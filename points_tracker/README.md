# ביס

אפליקציית ווב (מותקנת כאפליקציה בטלפון) למעקב ניקוד אוכל, מים ומשקל, עם סוכן חכם:

- **ניקוד מצילום** – מצלמים את המנה מתוך האפליקציה (בקשת הרשאה למצלמה). רק אם המצלמה לא זמינה
  (אין הרשאה / דפדפן לא תומך) מופיעה העלאה מהגלריה.
- **ניקוד מתיאור או ממרכיבים** – "חצי פיתה עם שוקולד", "2 משולשי פיצה", או רשימת מרכיבים של מתכון
  ("... יוצא 12 עוגיות"). הסוכן מפרק לרכיבים עם משקל, מתאים לפריטים מהמאגר, והאפליקציה מחשבת נקודות.
  אפשר לתקן גרמים של כל רכיב, להסיר רכיב ולשנות את מספר המנות.
- **חלק ממאכל** – לכל מאכל בוחרים כמות: ¼, ⅓, ½, ¾, 1, 1.5, 2, 3 או כל מספר. כמה מאכלים
  נאספים ל"צלחת" ונרשמים יחד (למשל חצי פיתה + שוקולד).
- **סריקת תווית** – במחשבון: מצלמים את טבלת הערכים התזונתיים והשדות מתמלאים.
- **הוספת מאכלים – ידנית ואוטומטית, בנפרד:**
  - **ידנית:** בהגדרות → "מאגר המאכלים" מוסיפים, עורכים ומוחקים מאכל וניקוד. גם במסך ההוספה יש
    "למאגר בלבד" (בלי לרשום ביומן) או "לצלחת ולמאגר".
  - **אוטומטית באפליקציה:** כשמחפשים מאכל שלא נמצא, הסוכן מחפש ברשת ומוסיף אותו למאגר בעצמו,
    בלי ללחוץ על כלום (אפשר לכבות בהגדרות).
  - **אוטומטית ב-GitHub:** פעם בשבוע הסוכן מוצא מאכלים פופולריים שחסרים ומוסיף אותם למאגר המשותף.
    בקשה ממך (issue או הרצה ידנית) רצה מיד.
  - שני המסלולים לא תלויים זה בזה: הסוכן לעולם לא דורס מאכל שהוספת ידנית, ומה שהוספת ידנית גובר
    על ערך של הסוכן באותו שם.

כתובת: **https://bis-app.pages.dev** (Cloudflare Pages, `.github/workflows/bis-deploy.yml`). בטלפון: "הוסף למסך הבית".
הכתובת הישנה ב-GitHub Pages (`/points/`) מעבירה אוטומטית לכתובת החדשה.
הטוקן של Cloudflare צריך גם הרשאת **Cloudflare Pages: Edit** (חוץ מהרשאות Workers).

## הנוסחה

`נקודות = חלבון/10.9375 + פחמימות/9.2105 + שומן/3.8889 − סיבים/12.5` (לפי 100 גרם, מוכפל במשקל המנה).
אותה נוסחה בדיוק ב-`web/src/lib/points.js` וב-`points.py`, ויש בדיקות שמוודאות שהן זהות.
הסוכן מחזיר ערכים תזונתיים בלבד; הנקודות תמיד מחושבות בקוד, כך שהן עקביות. אם הסוכן מצא ברשת ערך
נקודות שפורסם, הוא מוצג לידו לעיון.

## הסוכן ב-GitHub (`.github/workflows/points-agent.yml`)

מוסיף מאכלים ל-`data/foods.json`, מבצע commit ומפרסם מחדש את האפליקציה:

1. **בקשה (רצה מיד)** – פותחים issue עם התווית `food-request` וכותרת כמו `ניקוד: במבה נוגט`
   (באפליקציה, כשמאכל לא נמצא, יש קישור שפותח את זה מוכן). הסוכן עונה בתגובה עם הניקוד והמקורות
   וסוגר את ה-issue. רק בעל המאגר (או `POINTS_ALLOWED_AUTHORS`) יכול להפעיל אותו.
2. **סריקה שבועית אוטומטית** – כל יום ראשון בבוקר הסוכן סורק אתרי סופרמרקטים, יצרנים, רשתות מסעדות ופורומים של
   דיאטת נקודות, מוצא מאכלים פופולריים שחסרים במאגר (ברירת מחדל 10) ומוסיף אותם.
3. **ידני (רץ מיד)** – Actions → Points food agent → Run workflow, עם רשימת מאכלים מופרדת ב-`;`.

הגדרות (Settings → Secrets and variables → Actions):

| שם | סוג | |
|---|---|---|
| `ANTHROPIC_API_KEY` | secret | כבר קיים (משמש גם את הטוטו) |
| `POINTS_MODEL` | variable | ברירת מחדל `claude-opus-5-5` |
| `POINTS_DISCOVER_COUNT` | variable | כמה מאכלים להוסיף בכל שבוע (10; `0` מכבה) |
| `POINTS_ALLOWED_AUTHORS` | variable | משתמשי GitHub שמותר להם לבקש, מופרדים בפסיק |

עלות משוערת: כ-5–15 סנט למאכל (חיפושים ברשת + טוקנים), כלומר בערך 2–6 דולר בחודש עם 10 מאכלים
בשבוע, ועוד כמה סנטים לכל בקשה. כל הרצה רושמת את העלות ב-Summary.

## הסוכן בתוך האפליקציה: שרת משותף עם המפתח שלך

המפתח של Anthropic נשמר בשרת קטן וחינמי ב-Cloudflare (`proxy/worker.js`), לא בטלפונים ולא בקוד הציבורי
של האתר. מי שמשתמש באפליקציה צריך רק **קוד גישה**, ומי שנכנס מ**קישור ההזמנה** מקבל אותו אוטומטית.
כל טלפון שומר יומן, צלחת וניקוד משלו; רק המאגר הכללי של המאכלים משותף.

השרת מקבל רק בקשות עם קוד הגישה, רק את המודלים של האפליקציה ורק את סוגי הבקשות שלה.

### הקמה (פעם אחת, כ-10 דקות)

1. נרשמים בחינם ל-Cloudflare: https://dash.cloudflare.com/sign-up
2. נכנסים פעם אחת ל-**Workers & Pages**: https://dash.cloudflare.com/?to=/:account/workers-and-pages
   (אם מבקשים לבחור שם לתת-הדומיין `workers.dev`, בוחרים). בצד של הדף מופיע **Account ID** - מעתיקים.
3. יוצרים טוקן: https://dash.cloudflare.com/profile/api-tokens → **Create Token** → בתבנית
   **Edit Cloudflare Workers** לוחצים **Use template** → ב-Account Resources בוחרים את החשבון, ב-Zone Resources
   **All zones** → **Continue to summary** → **Create Token** → מעתיקים.
4. ב-GitHub: https://github.com/guygitter-bot/red-grass/settings/secrets/actions → **New repository secret**,
   שלושה סודות:
   - `CLOUDFLARE_API_TOKEN` - הטוקן משלב 3
   - `CLOUDFLARE_ACCOUNT_ID` - ה-Account ID משלב 2
   - `POINTS_ACCESS_CODE` - קוד גישה שתבחר (לפחות 8 תווים, אותיות ומספרים)
   - `POINTS_ADMIN_CODE` - קוד מנהל, שונה מקוד הגישה, רק בשבילך

   השרת משתמש במפתח `ANTHROPIC_API_KEY` שכבר קיים. כדי להשתמש במפתח נפרד לאפליקציה, מוסיפים
   `POINTS_ANTHROPIC_API_KEY`.
5. Actions → **Points proxy server** → **Run workflow**. השרת עולה, הכתובת שלו נכתבת לאפליקציה והאתר
   מתפרסם מחדש (כ-2 דקות).
6. באפליקציה: הגדרות → "הסוכן החכם" → מזינים את קוד הגישה → **בדוק חיבור** → **שלח קישור הזמנה**.
   שולחים את הקישור הזה למי שרוצים (במקום הקישור הרגיל).

### מאגר מאכלים משותף

מאכל חדש שמישהו מוסיף באפליקציה, ידנית או דרך הסוכן, נשמר גם בשרת (Durable Object ב-Cloudflare, חינמי)
ומופיע אצל כל המשתמשים בפתיחה הבאה. מאכל שכבר קיים באותו שם לא נדרס.
- **עריכה ומחיקה אישיות:** משפיעות רק על המכשיר של מי שעשה אותן.
- **מנהל:** מי שמזין בהגדרות את **קוד המנהל** (`POINTS_ADMIN_CODE`), העריכה והמחיקה שלו של מאכל משותף
  חלות על כולם. זה הכלי לתקן טעויות.

### החלפת מפתח או קוד

- **מפתח חדש:** מעדכנים את הסוד ב-GitHub ומריצים שוב את Points proxy server. מתעדכן אצל כולם.
- **קוד גישה חדש** (למשל אם קישור ההזמנה הגיע למישהו שלא צריך): מעדכנים את `POINTS_ACCESS_CODE`, מריצים
  שוב, ושולחים קישור הזמנה חדש למי שצריך. הקוד הישן מפסיק לעבוד מיד.
- מגבלת הוצאה חודשית: https://console.anthropic.com/settings/limits

מי שרוצה יכול עדיין להזין מפתח API אישי בהגדרות ("מפתח API אישי (לא חובה)"), והוא גובר על השרת.

## פיתוח

```bash
cd points_tracker/web
npm install
npm run dev      # http://localhost:5173
npm test
cd ../proxy && npm test
cd ../.. && python -m unittest discover -s points_tracker/tests -t .
```

הנתונים האישיים (יומן, משקל, מים, מאכלים שהוספת) נשמרים ב-localStorage, באותם מפתחות כמו בגרסה
הקודמת, כך שהנתונים הקיימים נשמרים. גיבוי ושחזור מקובץ – בהגדרות.
