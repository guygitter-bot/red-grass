# מעקב נקודות

אפליקציית ווב (מותקנת כאפליקציה בטלפון) למעקב נקודות, מים ומשקל, עם סוכן חכם:

- **ניקוד מצילום** – מצלמים את המנה מתוך האפליקציה (בקשת הרשאה למצלמה). רק אם המצלמה לא זמינה
  (אין הרשאה / דפדפן לא תומך) מופיעה העלאה מהגלריה.
- **ניקוד מתיאור או ממרכיבים** – "חצי פיתה עם שוקולד", "2 משולשי פיצה", או רשימת מרכיבים של מתכון
  ("... יוצא 12 עוגיות"). הסוכן מפרק לרכיבים עם משקל, מתאים לפריטים מהמאגר, והאפליקציה מחשבת נקודות.
  אפשר לתקן גרמים של כל רכיב, להסיר רכיב ולשנות את מספר המנות.
- **חלק ממאכל** – לכל מאכל בוחרים כמות: ¼, ⅓, ½, ¾, 1, 1.5, 2, 3 או כל מספר. כמה מאכלים
  נאספים ל"צלחת" ונרשמים יחד (למשל חצי פיתה + שוקולד).
- **סריקת תווית** – במחשבון: מצלמים את טבלת הערכים התזונתיים והשדות מתמלאים.
- **הוספת מאכלים – ידנית ואוטומטית, בנפרד:**
  - **ידנית:** בהגדרות → "מאגר המאכלים" מוסיפים, עורכים ומוחקים מאכל וניקוד. גם במסך ההוספה יש
    "למאגר בלבד" (בלי לרשום ביומן) או "לצלחת ולמאגר".
  - **אוטומטית באפליקציה:** כשמחפשים מאכל שלא נמצא, הסוכן מחפש ברשת ומוסיף אותו למאגר בעצמו,
    בלי ללחוץ על כלום (אפשר לכבות בהגדרות).
  - **אוטומטית ב-GitHub:** כל יום הסוכן מוצא מאכלים פופולריים שחסרים ומוסיף אותם למאגר המשותף.
  - שני המסלולים לא תלויים זה בזה: הסוכן לעולם לא דורס מאכל שהוספת ידנית, ומה שהוספת ידנית גובר
    על ערך של הסוכן באותו שם.

כתובת: `https://<user>.github.io/red-grass/points/`. בטלפון: "הוסף למסך הבית".

## הנוסחה

`נקודות = חלבון/10.9375 + פחמימות/9.2105 + שומן/3.8889 − סיבים/12.5` (לפי 100 גרם, מוכפל במשקל המנה).
אותה נוסחה בדיוק ב-`web/src/lib/points.js` וב-`points.py`, ויש בדיקות שמוודאות שהן זהות.
הסוכן מחזיר ערכים תזונתיים בלבד; הנקודות תמיד מחושבות בקוד, כך שהן עקביות. אם הסוכן מצא ברשת ערך
נקודות שפורסם, הוא מוצג לידו לעיון.

## הסוכן ב-GitHub (`.github/workflows/points-agent.yml`)

מוסיף מאכלים ל-`data/foods.json`, מבצע commit ומפרסם מחדש את האפליקציה:

1. **בקשה** – פותחים issue עם התווית `food-request` וכותרת כמו `ניקוד: במבה נוגט`
   (באפליקציה, כשמאכל לא נמצא, יש קישור שפותח את זה מוכן). הסוכן עונה בתגובה עם הניקוד והמקורות
   וסוגר את ה-issue. רק בעל המאגר (או `POINTS_ALLOWED_AUTHORS`) יכול להפעיל אותו.
2. **סריקה יומית אוטומטית** – כל יום הסוכן סורק אתרי סופרמרקטים, יצרנים, רשתות מסעדות ופורומים של
   דיאטת נקודות, מוצא מאכלים פופולריים שחסרים במאגר (ברירת מחדל 3 ביום) ומוסיף אותם.
3. **ידני** – Actions → Points food agent → Run workflow, עם רשימת מאכלים מופרדת ב-`;`.

הגדרות (Settings → Secrets and variables → Actions):

| שם | סוג | |
|---|---|---|
| `ANTHROPIC_API_KEY` | secret | כבר קיים (משמש גם את הטוטו) |
| `POINTS_MODEL` | variable | ברירת מחדל `claude-opus-5-5` |
| `POINTS_DISCOVER_COUNT` | variable | כמה מאכלים להוסיף בכל יום (3; `0` מכבה) |
| `POINTS_ALLOWED_AUTHORS` | variable | משתמשי GitHub שמותר להם לבקש, מופרדים בפסיק |

עלות משוערת: כ-5–15 סנט למאכל (חיפושים ברשת + טוקנים), כלומר בערך 5–15 דולר בחודש עם 3 מאכלים
ביום. כל הרצה רושמת את העלות ב-Summary.

## הסוכן בתוך האפליקציה

הגדרות → "הסוכן החכם": מדביקים מפתח API של Anthropic. המפתח נשמר רק בטלפון, לא בגיבוי, והבקשות
יוצאות ישירות מהדפדפן ל-Anthropic. בלי מפתח האפליקציה עובדת כרגיל (חיפוש, מחשבון, צלחת), רק בלי
צילום / ניתוח טקסט / חיפוש ברשת.

## פיתוח

```bash
cd points_tracker/web
npm install
npm run dev      # http://localhost:5173
npm test
cd ../.. && python -m unittest discover -s points_tracker/tests -t .
```

הנתונים האישיים (יומן, משקל, מים, מאכלים שהוספת) נשמרים ב-localStorage, באותם מפתחות כמו בגרסה
הקודמת, כך שהנתונים הקיימים נשמרים. גיבוי ושחזור מקובץ – בהגדרות.
