# mat-kon · מתכונים

ספר מתכונים שמסדר את עצמו: מדביקים (או משתפים מהטלפון) קישור למתכון מכל אתר, או לסרטון
ב-YouTube / TikTok / Instagram / Facebook, והאפליקציה מוציאה ממנו מתכון מסודר בעברית ומכניסה אותו
לקטגוריה המתאימה.

כתובת: **https://mat-kon.pages.dev**. בטלפון: "הוסף למסך הבית", ואז אפשר לשתף קישור ישירות
ל-mat-kon מכל אפליקציה (באנדרואיד; באייפון מדביקים בשדה או לוחצים "הדבקה").

## מה יש בכל מתכון

- **הקישור המקורי בראש הדף** (ולסרטון גם נגן מוטמע)
- שם, תיאור, קטגוריה (אפשר לשנות), תגיות, כמות מנות וזמנים
- **מצרכים** (מחולקים לקטעים כמו "לבצק" / "לציפוי") עם סימון תוך כדי בישול
- **אופן ההכנה** בשלבים ממוספרים, וטיפים מהמקור
- הערה מהסוכן מאיפה המתכון נלקח (דף, תיאור הסרטון, כתוביות, מתכון מקביל) ומה הוערך
- ההערות שלי, מועדפים, עריכה, רענון מהמקור, חיפוש לפי שם / מצרך / תגית / ערוץ

## ייבוא מווטסאפ

במסך הבית: **"ייבוא מתכונים מצ'אט או מקבוצה בווטסאפ"**. ווטסאפ לא מאפשר לאפליקציות לקרוא צ'אטים,
ולכן מייצאים את הצ'אט (מתוך הצ'אט או הקבוצה: ייצוא צ'אט ← **ללא מדיה**):

- **אנדרואיד:** בוחרים בשיתוף את **mat-kon** (כשהאפליקציה מותקנת במסך הבית) והמסך נפתח עם הצ'אט,
  או שומרים את הקובץ ובוחרים אותו במסך הייבוא.
- **אייפון:** שומרים בקבצים ובוחרים את קובץ ה-zip במסך הייבוא.

הסריקה נעשית בטלפון (`web/src/lib/whatsapp.js`): כל הקישורים (כל קישור פעם אחת, גם אם שותף כמה פעמים
ובצורות שונות) ומתכונים שנכתבו כהודעה. קישורים שנראים כמו מתכון או סרטון מסומנים מראש, קישורים
כמו מפות וזום מדולגים, ומה שכבר בספר מסומן "כבר בספר". בוחרים ומייבאים: קישור עובר את הסידור הרגיל,
והודעה כתובה מסודרת מהטקסט שלה (`POST /recipes/text`, בלי חיפוש ברשת). בדף מתכון מווטסאפ מופיעים
בראש הדף הצ'אט, השולח והתאריך, ואפשר לפתוח את ההודעה המקורית. כל פריט שמיובא נספר במכסה של משתמש
שהוזמן, והייבוא נעצר כשהמכסה נגמרת.

## איך זה עובד

1. השרת (`api/source.js`) קורא את הקישור: נתוני מתכון מובנים (schema.org) מהדף, כותרת ותמונה,
   ובסרטון – התיאור, הכתוביות ו-oEmbed.
2. הסוכן (`api/extract.js`, Claude Opus 5.5) מסדר מזה מתכון בעברית ובוחר קטגוריה. כשהחומר חסר
   (סרטון בלי מתכון בתיאור, אתר שחוסם) הוא קורא את הקישור בעצמו ומחפש ברשת את המתכון הכתוב של היוצר.
   דף עם מתכון מובנה מלא עובר בלי חיפוש ברשת – מהיר וזול.
3. המתכון נשמר בספר המתכונים בשרת (Durable Object), כך שהוא זמין מכל מכשיר. קישור שכבר נשמר מתעדכן
   ולא נכפל.

**סרטונים ורשתות חברתיות** (`api/social.js`): המתכון הרבה פעמים לא בסרטון אלא בכיתוב, בתגובה של היוצר
("המתכון בתגובות") או בבלוג. לכן נקראים: באינסטגרם – הכיתוב והתגובות מדף ה-embed הציבורי ומהשאילתה
הציבורית של הפוסט; ביוטיוב – התיאור, הכתוביות והתגובות (כולל המוצמדת); בטיקטוק – הכיתוב והתגובות.
התגובות של היוצר מסומנות ונשלחות ראשונות, וקישורים לאתרים שמופיעים בכיתוב או בתגובות נקראים גם הם.
בייבוא מווטסאפ, מה שנכתב בהודעה ליד הקישור נשלח לסוכן כרמז. הסוכן מוותר ("לא נמצא מתכון") רק כשהקישור
לא קשור לאוכל; כשהמנה ברורה אבל הכמויות לא נמצאות הוא משלים ממתכון מקביל ומסמן זאת בהערה.

**פייסבוק:** דף רגיל מחזיר שגיאה בלי התחברות, אבל לבוט התצוגה המקדימה של פייסבוק עצמו מוחזרים כותרת
הפוסט (ולפעמים כל הטקסט), גם בקבוצות – זה מה שנקרא.

**הדבקת טקסט:** כשקישור לא נקרא (קבוצה סגורה, מתכון רק בתגובות), בפריט שנכשל יש "הדבקת טקסט מהפוסט":
פותחים את הפוסט באפליקציה שבה מחוברים, מעתיקים את הטקסט או את התגובה עם המתכון ומדביקים. המתכון נבנה
מהטקסט (`POST /recipes/text` עם `url`), הקישור המקורי נשאר בראש הדף, ו"רענון מהמקור" בונה שוב מאותו טקסט.
לא מחברים חשבונות פייסבוק/אינסטגרם/טיקטוק לשרת: גלישה אוטומטית עם חשבון אישי משרת בענן עלולה לגרום
לנעילת החשבון, ושמירת ההתחברות בשרת נותנת גישה מלאה לחשבון.

**בדיקת קישור:** Actions → **mat-kon probe** → Run workflow → מדביקים קישור, ורואים מה השרת הצליח לקרוא
(כיתוב, תגובות, מתכון מובנה, מה נחסם) – בלי AI ובלי לשמור. אם אינסטגרם משנה את השאילתה הציבורית, אפשר
להגדיר משתנה `IG_DOC_ID` ב-`api/wrangler.toml` בלי שינוי קוד.

הקטגוריות: `api/categories.js` (אותה רשימה ב-`web/src/lib/categories.js`, יש בדיקה שמוודאת).

## שני סוגי שימוש

- **בעל האפליקציה (את/ה):** https://mat-kon.pages.dev פתוח לגמרי – בלי קוד, בלי הרשמה ובלי הגבלה.
- **משתמש שהוזמן:** בכפתור **הזמנות** (למעלה במסך הבית) יוצרים קישור הזמנה ושולחים אותו. מי שפותח אותו
  נרשם (שם, אימייל, סיסמה) ומקבל ספר מתכונים ריק משלו, שרק הוא רואה. כל קישור טוב להרשמה אחת.
  ממכשיר נוסף נכנסים עם האימייל והסיסמה (`https://mat-kon.pages.dev/#login`).
  - **10 המתכונים הראשונים בחינם** (נספרים מתכונים חדשים; רענון או אותו קישור שוב לא נספרים, ומחיקה
    לא מחזירה מכסה). אחר כך הוספה נחסמת עם מסך "שדרוג", והמתכונים הקיימים נשארים זמינים.
  - **הכנה לתשלום:** במסך ההזמנות מסמנים משתמש כ"מנוי בתשלום" ואז אין לו הגבלה. כשתהיה סליקה,
    שמים ב-`PAYMENT_URL` (ב-`api/wrangler.toml`) את הקישור לדף התשלום ובמסך השדרוג יופיע כפתור אליו.
    את מספר המתכונים החינמיים משנים ב-`FREE_RECIPES`.
  - מחיקת הזמנה של משתמש רשום מוחקת אותו ואת כל המתכונים שלו.

שימו לב: כיוון שהאפליקציה הראשית פתוחה, כל מי שמגיע לכתובת בלי להירשם רואה את הספר שלך ואת
מסך ההזמנות. מכשיר שנרשם פעם מקישור הזמנה נשאר במצב משתמש מוזמן גם אחרי יציאה.

## הקמה

הפריסה אוטומטית ב-`.github/workflows/mat-kon.yml` בכל שינוי ב-`mat_kon/` שנכנס ל-`main`
(או ידנית: Actions → mat-kon → Run workflow). משתמשת בסודות שכבר קיימים במאגר:

| סוד | |
|---|---|
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | כבר קיימים (הטוקן צריך גם Cloudflare Pages: Edit) |
| `ANTHROPIC_API_KEY` | כבר קיים. למפתח נפרד: `MATKON_ANTHROPIC_API_KEY` |

עלות משוערת: כמה סנטים למתכון מאתר עם נתונים מובנים, ועד כ-10–20 סנט לסרטון שדורש חיפוש ברשת.
משתמשים מוזמנים משתמשים באותו מפתח, ולכן המכסה החינמית מגבילה גם את העלות שלהם.
