# mat-kon · מתכונים

ספר מתכונים שמסדר את עצמו: מדביקים (או משתפים מהטלפון) קישור למתכון מכל אתר, או לסרטון
ב-YouTube / TikTok / Instagram / Facebook, והאפליקציה מוציאה ממנו מתכון מסודר בעברית ומכניסה אותו
לקטגוריה המתאימה.

כתובת: **https://mat-kon.pages.dev**. בטלפון: "הוסף למסך הבית", ואז אפשר לשתף קישור ישירות
ל-mat-kon מכל אפליקציה (באנדרואיד; באייפון מדביקים בשדה או לוחצים "הדבקה").

## מה יש בכל מתכון

- **הקישור המקורי בראש הדף** (ולסרטון גם נגן מוטמע)
- שם, תיאור, קטגוריה (אפשר לשנות), תגיות, כמות מנות וזמנים
- **מצרכים** (מחולקים לקטעים כמו "לבצק" / "לציפוי") עם סימון תוך כדי בישול
- **אופן ההכנה** בשלבים ממוספרים, וטיפים מהמקור
- הערה מהסוכן מאיפה המתכון נלקח (דף, תיאור הסרטון, כתוביות, מתכון מקביל) ומה הוערך
- ההערות שלי, מועדפים, עריכה, רענון מהמקור, חיפוש לפי שם / מצרך / תגית / ערוץ

## במטבח

- **שינוי מספר מנות:** בדף המתכון, ליד המצרכים. כשכתוב כמה מנות ("8 מנות") – פלוס/מינוס; אחרת מכפיל
  (½, ×1.5, ×2, ×3). הכמויות מוכפלות (גם שברים: ¾ כוס ×1.5 = 1⅛ כוס), בלי לגעת באחוזים, ס"מ, מעלות וזמנים
  (`web/src/lib/scale.js`). הבחירה נשמרת לכל מתכון במכשיר.
- **רשימת קניות** (כפתור העגלה למעלה): "לרשימת קניות" בדף מתכון מוסיף את המצרכים לפי מספר המנות שנבחר.
  אפשר להוסיף פריטים, לסמן מה נקנה, לשתף בווטסאפ, ו"סידור חכם" מאחד כפילויות (2 כוסות קמח + 1 כוס קמח)
  ומסדר לפי מחלקות בסופר. הרשימה נשמרת בשרת, משותפת לכל המכשירים של אותו ספר (משתמש מוזמן – רשימה משלו).
- **מתכון חדש בלי קישור:** "צילום מתכון" – כפתור המצלמה באמצע הסרגל התחתון (פותח את המצלמה ישר, ועובר לבניית
  המתכון עם התמונה), או "כתיבה ידנית" במסך הראשי. מצלמים עד 4 תמונות (דף מספר, פתק בכתב יד, צילום
  מסך) והסוכן קורא אותן ובונה מתכון; או כותבים בעצמכם (בלי AI ובלי מכסה). אפשר להוסיף/להחליף תמונה גם בעריכה.
- **מצב בישול:** בדף המתכון ליד "אופן ההכנה". המסך לא נכבה, שלב אחד בכל פעם בגדול, מצרכים בלחיצה, וטיימרים
  לכל זמן שכתוב בשלב ("אופים 30-35 דקות", "שעה וחצי") עם צפצוף ורטט בסוף (`web/src/lib/timers.js`).

- **תכנון ארוחות שבועי** (בסרגל התחתון): שבוע מראשון עד שבת, מעבר בין שבועות. לכל יום מוסיפים מתכון
  מהספר או הערה חופשית ("ארוחה בחוץ"), ובוחרים ארוחה (בוקר/צהריים/ערב). מדף מתכון: כפתור לוח השנה → יום
  בשבועיים הקרובים. "רשימת קניות לכל השבוע" מוסיף את המצרכים של כל המתכונים בשבוע, לפי מספר המנות שנבחר
  לכל אחד. נשמר בשרת (`GET/PUT /plan`), ימים ישנים מחודשיים נמחקים.
- **מקרר ומזווה** (בסרגל התחתון): שני כפתורים גדולים, מקרר ומזווה. כל אחד פותח מסך עם רשימה מסודרת של
  המוצרים (שורה לכל מוצר, עם הכמות). נשמר בשרת (`GET/PUT /pantry`).
  - **צילום מוצר**: מצלמים מוצר אחד והוא מזוהה ונכנס מיד.
  - **צילום כל המקרר / מדף במזווה** (עד 4 תמונות): הסוכן ממפה את כל המוצרים, ומאשרים (ומתקנים) לפני שהם
    נכנסים (`POST /pantry/scan`, לא שומר בעצמו). אפשר גם לכתוב.
  - **מה אפשר לבשל**: "מהספר שלי" – מתכונים מהספר לפי כמה מהמצרכים כבר יש ומה חסר (בטלפון, בלי AI,
    `web/src/lib/fridge.js`, מזהה רבים/יחיד ותחיליות, ואפשר להניח שמצרכי בסיס יש בבית). "חיפוש ברשת" –
    הסוכן מחפש מתכונים שמשתמשים בעיקר במה שיש (`POST /pantry/ideas`), ובוחרים מה להוסיף לספר.
- **איפה לקנות הכי זול** (ברשימת הקניות): לוקח את כל המוצרים שעוד לא נקנו ובונה מהם סל. בדף מתכון מופיע מה
  חסר בבית לפי המלאי, ו"רק החסרים לרשימת הקניות". הכפתור מבקש מיקום רק כשלוחצים עליו (המיקום לא נשמר),
  ו-`POST /stores` מחזיר:
  - סופרים קרובים מ-OpenStreetMap (Overpass), עם ניווט ב-Waze וקישור להזמנה אונליין לרשתות שיש להן אתר
    הזמנות (שופרסל, רמי לוי, יוחננוף, ויקטורי, קרפור, חצי חינם, טיב טעם).
  - השוואת מחירים לסל בכל רשת: עם מפתח Cheapersal – מחירים אמיתיים מהמחירון של הרשתות בעיר (הסוכן מוצא
    ברקוד למוצר נפוץ לכל מצרך, ומשם `api.cheapersal.co.il/api/v1/products/:barcode/prices`, כולל מבצעים בלי
    מועדון). בלי מפתח, או כשלא נמצא ברקוד – הערכה לפי מחירים ברשת (`api/stores.js`).

## ארגון הספר

- **חיפוש מתכון ברשת לפי שם:** "חיפוש מתכון ברשת" (או כותבים שם מנה בשדה ההוספה במקום קישור). הסוכן מחפש ומחזיר
  עד 6 מתכונים טובים (קודם אתרים ישראליים), ו"לספר" מוסיף כמו קישור רגיל (`POST /search`).
- **הקטגוריות שלי:** בספר המתכונים, בסוף שורת הקטגוריות, "+ קטגוריה" (למשל "מתכוני סבתא" או "לשבת"). הן מופיעות
  בספר ובבחירת קטגוריה, והסוכן משבץ בהן מתכונים חדשים כשהן מתאימות. כשקטגוריה שלכם נבחרת מופיע "מחיקה", והמתכונים
  שבה עוברים ל"אחר".
- **תגיות:** בדף מתכון מוסיפים (+ תגית) ומסירים (x). בספר יש שורת תגיות נפוצות לסינון.
- **דירוג בכוכבים** בדף המתכון, ומיון הספר לפי החדשים / א-ב / הדירוג הגבוה.
- **הדפסה / PDF:** בדף המתכון. בהדפסה מופיעים רק המתכון וההערות שלי, בלי כפתורים (ב"שמירה כ-PDF" של הדפדפן).
- **גיבוי ושחזור:** בהגדרות. "הורדת גיבוי" שומר קובץ JSON עם כל המתכונים והקטגוריות; "שחזור מקובץ" מוסיף אותם
  לספר (בלי AI ובלי מכסה), ומתכון שכבר קיים מתעדכן ולא נכפל (`POST /recipes/restore`).

## ייבוא מווטסאפ

במסך הבית: **"ייבוא מתכונים מצ'אט או מקבוצה בווטסאפ"**. ווטסאפ לא מאפשר לאפליקציות לקרוא צ'אטים,
ולכן מייצאים את הצ'אט (מתוך הצ'אט או הקבוצה: ייצוא צ'אט ← **ללא מדיה**):

- **אנדרואיד:** בוחרים בשיתוף את **mat-kon** (כשהאפליקציה מותקנת במסך הבית) והמסך נפתח עם הצ'אט,
  או שומרים את הקובץ ובוחרים אותו במסך הייבוא.
- **אייפון:** שומרים בקבצים ובוחרים את קובץ ה-zip במסך הייבוא.

הסריקה נעשית בטלפון (`web/src/lib/whatsapp.js`): כל הקישורים (כל קישור פעם אחת, גם אם שותף כמה פעמים
ובצורות שונות) ומתכונים שנכתבו כהודעה. קישורים שנראים כמו מתכון או סרטון מסומנים מראש, קישורים
כמו מפות וזום מדולגים, ומה שכבר בספר מסומן "כבר בספר". בוחרים ומייבאים: קישור עובר את הסידור הרגיל,
והודעה כתובה מסודרת מהטקסט שלה (`POST /recipes/text`, בלי חיפוש ברשת). בדף מתכון מווטסאפ מופיעים
בראש הדף הצ'אט, השולח והתאריך, ואפשר לפתוח את ההודעה המקורית. כל פריט שמיובא נספר במכסה של משתמש
שהוזמן, והייבוא נעצר כשהמכסה נגמרת.

## איך זה עובד

1. השרת (`api/source.js`) קורא את הקישור: נתוני מתכון מובנים (schema.org) מהדף, כותרת ותמונה,
   ובסרטון – התיאור, הכתוביות ו-oEmbed.
2. הסוכן (`api/extract.js`, Claude Opus 5.5) מסדר מזה מתכון בעברית ובוחר קטגוריה. כשהחומר חסר
   (סרטון בלי מתכון בתיאור, אתר שחוסם) הוא קורא את הקישור בעצמו ומחפש ברשת את המתכון הכתוב של היוצר.
   דף עם מתכון מובנה מלא עובר בלי חיפוש ברשת – מהיר וזול.
3. המתכון נשמר בספר המתכונים בשרת (Durable Object), כך שהוא זמין מכל מכשיר. קישור שכבר נשמר מתעדכן
   ולא נכפל.

**סרטונים ורשתות חברתיות** (`api/social.js`): המתכון הרבה פעמים לא בסרטון אלא בכיתוב, בתגובה של היוצר
("המתכון בתגובות") או בבלוג. לכן נקראים: באינסטגרם – הכיתוב והתגובות מדף ה-embed הציבורי ומהשאילתה
הציבורית של הפוסט; ביוטיוב – התיאור, הכתוביות והתגובות (כולל המוצמדת); בטיקטוק – הכיתוב והתגובות.
התגובות של היוצר מסומנות ונשלחות ראשונות, וקישורים לאתרים שמופיעים בכיתוב או בתגובות נקראים גם הם.
בייבוא מווטסאפ, מה שנכתב בהודעה ליד הקישור נשלח לסוכן כרמז. הסוכן מוותר ("לא נמצא מתכון") רק כשהקישור
לא קשור לאוכל; כשהמנה ברורה אבל הכמויות לא נמצאות הוא משלים ממתכון מקביל ומסמן זאת בהערה.

**פייסבוק:** דף רגיל מחזיר שגיאה בלי התחברות, אבל לבוט התצוגה המקדימה של פייסבוק עצמו מוחזרים כותרת
הפוסט (ולפעמים כל הטקסט), גם בקבוצות – זה מה שנקרא.

**הדבקת טקסט:** כשקישור לא נקרא (קבוצה סגורה, מתכון רק בתגובות), בפריט שנכשל יש "הדבקת טקסט מהפוסט":
פותחים את הפוסט באפליקציה שבה מחוברים, מעתיקים את הטקסט או את התגובה עם המתכון ומדביקים. המתכון נבנה
מהטקסט (`POST /recipes/text` עם `url`), הקישור המקורי נשאר בראש הדף, ו"רענון מהמקור" בונה שוב מאותו טקסט.
לא מחברים חשבונות פייסבוק/אינסטגרם/טיקטוק לשרת: גלישה אוטומטית עם חשבון אישי משרת בענן עלולה לגרום
לנעילת החשבון, ושמירת ההתחברות בשרת נותנת גישה מלאה לחשבון.

**בדיקת קישור:** Actions → **mat-kon probe** → Run workflow → מדביקים קישור, ורואים מה השרת הצליח לקרוא
(כיתוב, תגובות, מתכון מובנה, מה נחסם) – בלי AI ובלי לשמור. אם אינסטגרם משנה את השאילתה הציבורית, אפשר
להגדיר משתנה `IG_DOC_ID` ב-`api/wrangler.toml` בלי שינוי קוד.

הקטגוריות: `api/categories.js` (אותה רשימה ב-`web/src/lib/categories.js`, יש בדיקה שמוודאת).

## שני סוגי שימוש

- **בעל האפליקציה (את/ה):** https://mat-kon.pages.dev – בלי הגבלה. פתוח לכל מי שיש לו את הכתובת, או נעול
  (`OWNER_PASSWORD` / `OWNER_EMAIL`): כל מכשיר של בעל האפליקציה נכנס פעם אחת, וכל השאר מקבלים מסך כניסה.
- **משתמש שהוזמן:** בכפתור **הזמנות** (למעלה במסך הבית) יוצרים קישור הזמנה ושולחים אותו. מי שפותח אותו
  נרשם (שם, אימייל וסיסמה, או "המשך עם Google") ומקבל ספר מתכונים ריק משלו, שרק הוא רואה. כל קישור טוב להרשמה אחת.
  ממכשיר נוסף נכנסים עם האימייל והסיסמה (`https://mat-kon.pages.dev/#login`).
  - **10 המתכונים הראשונים בחינם** (נספרים מתכונים חדשים; רענון או אותו קישור שוב לא נספרים, ומחיקה
    לא מחזירה מכסה). אחר כך הוספה נחסמת עם מסך "שדרוג", והמתכונים הקיימים נשארים זמינים.
  - **הכנה לתשלום:** במסך ההזמנות מסמנים משתמש כ"מנוי בתשלום" ואז אין לו הגבלה. כשתהיה סליקה,
    שמים ב-`PAYMENT_URL` (ב-`api/wrangler.toml`) את הקישור לדף התשלום ובמסך השדרוג יופיע כפתור אליו.
    את מספר המתכונים החינמיים משנים ב-`FREE_RECIPES`.
  - מחיקת הזמנה של משתמש רשום מוחקת אותו, את החברים בספר שלו ואת כל המתכונים.
- **ספר משותף (בן/בת זוג, משפחה):** בהגדרות ← **שיתוף הספר** בעל הספר (משתמש שהוזמן, או בעל האפליקציה
  לספר שלו) יוצר קישור הצטרפות (`#join=...`, להצטרפות אחת, תקף 7 ימים) ושולח אותו. מי שמצטרף נרשם עם
  החשבון שלו (גוגל או אימייל) ועובד על אותו ספר: מתכונים, קטגוריות, רשימת קניות, תכנון ומלאי. עד 5 אנשים
  בספר. המנוי והמכסה החינמית שייכים לבעל הספר ומשותפים לכולם; רק בעל הספר מנהל את השיתוף ויכול להסיר
  חבר. חבר בספר של בעל האפליקציה עובד בלי מכסה, אבל לא רואה את מסך ההזמנות.

**הגנות (QA סבב 2):**
- **מכסת המתכונים החינמיים** נלקחת לפני העבודה ומוחזרת אם לא נוסף מתכון, כך ששתי בקשות במקביל לא עוקפות אותה. מתכון ששוחזר מגיבוי נספר כשקוראים אותו מהמקור בפעם הראשונה.
- **תקציב יומי לפעולות AI** לכל ספר: `AI_DAILY_FREE` (ברירת מחדל 25), `AI_DAILY_PAID` (100), `AI_DAILY_OWNER` (300). חל על הוספה, רענון, צילום, חיפוש, מתכונים מהמלאי, "איפה לקנות" וסידור רשימה.
- **הגבלת קצב:** כניסה (לפי כתובת ולפי אימייל), סיסמת בעלים (לפי כתובת ותקרה כללית), הרשמה וגוגל.
- **חיבורים:** פגים אחרי 180 יום. החלפת סיסמת הבעלים מנתקת את כל מכשירי הבעלים. יש "יציאה מכל המכשירים" ו"מחיקת החשבון" בהגדרות.
- **כניסה עם גוגל לחשבון שנרשם עם סיסמה:** גוגל מוכיח שהאימייל שלו, ולכן הסיסמה מבוטלת וכל החיבורים מנותקים. כך אי אפשר לתפוס מראש חשבון עם אימייל של מישהו אחר.
- **הורדת דפים בשרת:** רק כתובות ציבוריות, גם אחרי הפניות, עם מגבלת זמן וגודל.
- **כותרות אבטחה לאתר** (`web/public/_headers`): CSP, מניעת הטמעה, הרשאות מצלמה ומיקום.
- **מיקום:** נשלח לשירותים חיצוניים בקירוב של כ-100 מטר.
- **גיבוי:** כולל גם מלאי. השחזור נשלח במנות ומשחזר מתכונים, רשימת קניות, תכנון ומלאי.

כשהספר של בעל האפליקציה לא נעול, כל מי שמגיע לכתובת בלי להירשם רואה את הספר שלך ואת מסך ההזמנות.
מכשיר שנרשם פעם מקישור הזמנה נשאר במצב משתמש מוזמן גם אחרי יציאה.

## הקמה

הפריסה אוטומטית ב-`.github/workflows/mat-kon.yml` בכל שינוי ב-`mat_kon/` שנכנס ל-`main`
(או ידנית: Actions → mat-kon → Run workflow). משתמשת בסודות שכבר קיימים במאגר:

| סוד | |
|---|---|
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | כבר קיימים (הטוקן צריך גם Cloudflare Pages: Edit) |
| `ANTHROPIC_API_KEY` | כבר קיים. למפתח נפרד: `MATKON_ANTHROPIC_API_KEY` |
| `GOOGLE_CLIENT_ID` | לא חובה (משתנה או סוד). מוסיף "המשך עם Google" להרשמה מקישור הזמנה ולכניסה. יוצרים ב-Google Cloud Console ← APIs & Services ← Credentials ← OAuth client ID ← Web application, עם Authorized JavaScript origin `https://mat-kon.pages.dev` |
| `OWNER_PASSWORD` | **נדרש** (או `OWNER_EMAIL` עם גוגל). בלי זה הספר של בעל האפליקציה סגור לכולם ("כשל סגור"); כדי להשאיר אותו פתוח בלי סיסמה צריך במפורש `OWNER_OPEN=true`. עם זה כל מכשיר נכנס פעם אחת ("בעל האפליקציה? כניסה עם סיסמת הבעלים") |
| `OWNER_EMAIL` | לא חובה. האימייל של חשבון הגוגל של בעל האפליקציה – כניסה לספר שלו עם "המשך עם Google" (גם נועל את הספר) |
| `CHEAPERSAL_API_KEY` | לא חובה. מחירים אמיתיים ב"איפה לקנות" ([מפתח חינמי](https://cheapersal.co.il/developers/keys), 100 בקשות ביום) |

עלות משוערת: כמה סנטים למתכון מאתר עם נתונים מובנים, ועד כ-10–20 סנט לסרטון שדורש חיפוש ברשת.
משתמשים מוזמנים משתמשים באותו מפתח, ולכן המכסה החינמית מגבילה גם את העלות שלהם.
