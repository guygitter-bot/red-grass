# Isport – חנות חולצות כדורגל

אתר שנראה כמו חנות חולצות, **בלי סליקה, בלי עגלה ובלי הזמנות**. הלקוח בוחר חולצה, שם, מספר, פאץ' ושרוול,
לוחץ "שמור" – והאתר יוצר **הערה למוכר** (מועתקת אוטומטית) ומעביר אותו לדף המוצר ב-FlyLinking, שם בוחרים מידה וגרסה.

- **קטגוריות** (המנהל מוסיף, משנה שם וסדר, ומסתיר בהגדרות). לכל קטגוריה סוג (`template`) שקובע מה מתאימים אישית:
  `football` – שם, מספר, פאץ' ושרוול; `basketball` – שם ומספר; `plain` (נעליים, תיקים…) – בלי התאמה, ההערה = קוד המוצר
  (במוצר רגיל: team = מותג, type = דגם). מוצר ישן בלי קטגוריה = חולצת כדורגל. קטגוריה עם מוצרים לא נמחקת – מסתירים.
- **חנות** – https://isport-shop.pages.dev : קטגוריות (`#/c/<id>`), חיפוש (קבוצה, נבחרת, מותג, סוג, שנה, צבע, קוד), קבוצות/נבחרות/ליגות, דף מוצר,
  מועדפים (בכל מכשיר בנפרד), שיתוף, וואטסאפ לשאלות.
- **ניהול** – `#/admin` בסיסמה: הוספה ועריכה, "מלא אוטומטית" (Claude: סיווג קבוצה/נבחרת, שם בעברית, מדינה, ליגה,
  תיאור ותגים + חיפוש תמונות ברשת), אישור עד 4 תמונות (או העלאה מהמכשיר / קישור), קוד מוצר אוטומטי או ידני,
  קישור FlyLinking, שרוול ארוך, מומלצת, פרסום/הסתרה, הגדרות (וואטסאפ, אינסטגרם, הודעה בראש האתר).

## ייבוא מערוץ טלגרם (`#/admin/import`)
מייצאים את הערוץ ב-Telegram Desktop (Photos, JSON, טווח תאריכים) ובוחרים את התיקייה במסך הניהול. הקריאה בדפדפן
(`web/src/lib/telegram.js`): אלבום = הודעות רצופות באותה שנייה; כל קוד (כמו `BocaJuniors-H-27`) = מוצר טיוטה מוסתר עם הקוד
המדויק (ידני), קישור FlyLinking מהפוסט ועד 4 תמונות; קוד עם `-LongSleeve` = שרוול ארוך לאותו מוצר. סינון לפי תאריכים, קוד
שכבר קיים לא מסומן. השלמה אוטומטית – רק אם מסמנים (עולה כסף).

## ההערה למוכר
```
Liverpool-Home-26-Red-LongSleeve     <- קוד המוצר (+ ShortSleeve/LongSleeve רק כשיש גרסת שרוול ארוך)
Name: Israel                          <- רק אם נבחר
Number: 10                            <- רק אם נבחר
Add League Patches                    <- רק אם נבחר פאץ'
```
קוד המוצר: `Team-Type-Year-Color` (שנה = שתי הספרות האחרונות). הקוד והפאצ'ים כפולים ב-`api/model.js` וב-`web/src/lib/shirt.js` – לשנות בשניהם.

## מבנה
- `api/` – Cloudflare Worker `isport-api` + Durable Object `Shop` אחד (`shop.js`). ניקוי נתונים ב-`model.js`, הסוכן ב-`ai.js`,
  תמונות ב-`images.js`. התמונות שאושרו נשמרות בדלי R2 `isport-images` ומוגשות מ-`/img/<שם>`.
- `web/` – React + Vite + Tailwind, RTL, טלפון + מחשב + מצב לילה. צבעי המותג ב-`src/index.css`, הלוגו: `public/logo.webp` (רקע שקוף) והאייקונים `icon-192/512.png`. תמונת הפתיחה: `hero-lg.webp` (מחשב) ו-`hero-sm.webp` (טלפון, חיתוך לאורך: השלט בחלק העליון השקוף והכיתוב מתחתיו), עם שכבה כהה רק מאחורי הכיתוב.

## אבטחה
- **שתי סיסמאות:** `ADMIN_PASSWORD` (סוד ב-GitHub) = מי שבנה את האתר (`dev`); בעל החנות (`client`) מקבל סיסמה שהמפתח קובע
  בהגדרות (PBKDF2 ב-`clientPass`; שינוי/ביטול מנתק אותו מיד). שחזור גיבוי וקביעת הסיסמה – רק `dev` (נבדק בשרת).
- כניסה נותנת אסימון אקראי (נשמר בשרת רק כ-hash, 30 יום). 6 ניסיונות שגויים = נעילה לחצי שעה.
- כל פעולת ניהול נבדקת בשרת. הלקוחות רואים רק חולצות שפורסמו, בלי שדות פנימיים.
- השרת עונה רק לאתר עצמו (CORS), עם מגבלת גודל לכל בקשה. CSP ושאר הכותרות ב-`web/public/_headers`.
- תמונות מהרשת: רק https לכתובת ציבורית, עד 6MB, ונבדק שהקובץ באמת תמונה (לפי הבייטים). מוגשות עם `nosniff` ו-sandbox.
- הסוכן: עד 300 הפעלות ביום. שום דבר ממנו לא נשמר בלי אישור.
- עלויות: השרת סופר לכל חודש טוקנים, חיפושים ברשת ומספר הפעלות (`usage:<YYYY-MM>`); בהגדרות טבלה חודשית בשקלים
  לפי המחירון (`web/src/lib/cost.js` – לעדכן אם המודל או המחיר משתנים). החשבון המדויק: Anthropic Console, מפתח `ISPORT_ANTHROPIC_API_KEY`.

## סודות ב-GitHub
`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` (קיימים), `ISPORT_ADMIN_PASSWORD` – הסיסמה למסך הניהול, ו-`ISPORT_ANTHROPIC_API_KEY` –
מפתח Claude נפרד לאתר (Workspace משלו ב-Anthropic Console, כדי לדעת בדיוק כמה עלה; בלעדיו – `ANTHROPIC_API_KEY` המשותף).
בלי הסיסמה מסך הניהול נעול (החנות עובדת).

## סרטוני הדרכה (`tutorials/`)
סרטונים: `order` (ללקוחות – בדף הבית, "איך זה עובד?"), `admin` (במסך הניהול) ו-`import` (במסך הייבוא מטלגרם; מוקלט במסך מחשב – `record(..., { desktop: true })`). מוקלטים אוטומטית מהאתר עם השרת האמיתי בזיכרון
(סוכן מדומה, בלי AI): `cd web && npm run build`, ואז `cd ../tutorials && node videos/<שם>.mjs`. **לא להקליט מחדש בלי לשאול את המשתמש** (אחרי שינוי במסך – לשאול אם לעדכן את הסרטון).
קריינות כמו ב-mat-kon: משפט חדש נכנס ל-`tutorials/voice/lines.json`; דחיפה לענף עבודה מפעילה את `isport-voice.yml`, שמחזיר את קובצי ה-MP3
(ElevenLabs, הקול "נועה"; Google TTS רק כגיבוי) לענף – ואז `git pull` ולהקליט שוב. מוזיקה: `tutorials/music.m4a` (אותה של mat-kon).

## גיבוי
- כל לילה (cron ב-`api/wrangler.toml`, ~3:30 בישראל): `backups/<YYYY-MM-DD>.json` בדלי `isport-images` – מוצרים, קטגוריות, הגדרות
  ושימוש. נשמר 30 יום. בהגדרות: רשימה, "גיבוי עכשיו", ושחזור (רק `dev`; לפני שחזור נשמר גיבוי `-restore`).
- תמונה שהוסרה ממוצר עוברת ל-`trash` ונמחקת מהדלי רק אחרי 31 יום – כדי שגיבוי ישן ישוחזר עם התמונות.
- שינוי במבנה הנתונים של מוצר – לוודא שהגיבוי והשחזור (`snapshot` / `restore` ב-`api/shop.js`) עדיין מכסים אותו.
