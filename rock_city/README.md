# רוק סיטי – מערכת שעות

מערכת השעות של בית הספר למוזיקה "רוק סיטי". בעברית, מימין לשמאל, לטלפון ולמחשב, עם מצב לילה. צבעי המותג מהלוגו: צהוב-זהב ושחור.

- **האפליקציה:** https://rock-city-school.pages.dev (אפשר להתקין במסך הבית)
- **השרת:** https://rock-city-api.guygitter.workers.dev

## מה יש
- **מערכת שעות** – ארבע תצוגות: יום (רשימה, נוח בטלפון), שבוע (לוח שעות, נוח במחשב), **חודש** (לוח שנה – לחיצה על יום פותחת אותו),
  ויום מחולק **לפי חדרים**.
  סינון לפי מורה / חדר / נושא. לחיצה על מקום ריק בלוח = שיעור חדש בשעה הזאת.
- **שיעור** – מורה, תלמיד אחד או כמה (להקה / קבוצה), נושא, חדר, כל שבוע (מתאריך עד תאריך) או פעם אחת, שעה ומשך.
  בפרטי השיעור: מצב התשלום של כל תלמיד (למנהלים), ומה קרה בתאריך מסוים – הגיע / לא הגיע / בוטל + הערה.
  "להזיז רק את השיעור הזה" – מבטל את השיעור בתאריך הזה ופותח שיעור חד-פעמי במקומו.
- **חדרים** (🚪) – לכל חדר: פנוי עכשיו / תפוס עד מתי, כמה שעות תפוס השבוע, ולכל יום בשבוע פס זמן עם החלונות הפנויים
  והתפוסים (בתוך שעות הפעילות – ב"עוד", ברירת מחדל 08:00–22:00). לחיצה על זמן פנוי = שיעור חדש באותו חדר ובאותה שעה.
- **יומן גוגל** (`web/src/lib/gcal.js`) – בכל שיעור: "ליומן שלי" (קישור של גוגל שמכניס את השיעור, שבועי – כל שבוע),
  ו"שליחה ל..." בוואטסאפ למורה ולתלמידים עם אותו קישור. בכרטיס מורה / תלמיד: "כל השיעורים ליומן גוגל" – קובץ יומן (`.ics`)
  עם כל השיעורים (בלי התאריכים שבוטלו), לשיתוף או להורדה. ייבוא הקובץ לגוגל: במחשב, calendar.google.com ← הגדרות ← ייבוא.
- **בדיקת התנגשויות** – כשמוסיפים או משנים שיעור: אותו חדר / אותו מורה / אותו תלמיד באותה שעה (12 השבועות הקרובים).
- **תלמידים** – שם, טלפון, כתובת, איש קשר וטלפון, תאריך לידה, מחיר לחודש, הערות, פעיל/לא פעיל. חיוג ווטסאפ בלחיצה.
- **מורים** – שם, תמונה, טלפון, מייל, מה מלמד, צבע בלוח, כמה שיעורים ושעות בשבוע.
- **תשלומים** (רק מנהלים) – כל תשלום "מכסה עד" תאריך; מזה מחושב כמה ימים נשארו לתשלום הבא.
  מסך מרוכז: לא שולם בזמן / בשבוע הקרוב / בלי תשלום / שולם, סכום החודש, ותזכורת בוואטסאפ להורה.
- **התראות ובקשות** (🔔) – ראו "הרשאות".
- **עוד** – הפרטים של המנהל (תמונה, שם, טלפון – מוצגים גם למורים), חדרים ונושאים (אפשר להוסיף), חשבון המנהל,
  **מורים והרשאות** (רשימה עם שינוי הרשאה ומחיקה – הקישור של מורה שנמחק מפסיק לעבוד; למורה עם שיעורים אפשר רק לבטל גישה),
  הורדת גיבוי (JSON), יומן שינויים.

## הרשאות
- **מנהל** – שם משתמש וסיסמה. בפעם הראשונה שפותחים את האפליקציה בוחרים אותם (רק פעם אחת – אחר כך זו כניסה רגילה).
  8 ניסיונות שגויים = נעילה לרבע שעה.
- **מורים** נכנסים בקישור אישי (`#k=<סוד>`) שהמנהל יוצר בכרטיס המורה ושולח בוואטסאפ. קישור חדש מבטל את הקודם; אפשר לבטל גישה.
  - **צפייה בלבד** – רואה הכול חוץ מתשלומים ויומן. לא משנה כלום, אבל יכול לאשר בקשות על השיעורים שלו.
  - **עריכת השיעורים שלו** – משנה את השיעורים שלו מיד (המשרד מקבל התראה). שינוי בשיעור של מורה אחר **נשלח כבקשה**
    לאותו מורה (התראה + אפשרות לשלוח לו גם וואטסאפ), ומתבצע רק אחרי אישור. מוסיף ועורך תלמידים.
  - **ניהול מלא** – כמו המנהל (כולל תשלומים, חדרים ונושאים), חוץ מהרשאות וקישורים.
- כשהמנהל משנה שיעור – המורה של השיעור מקבל התראה.
- השרת בודק את כל ההרשאות (לא רק האפליקציה), ושולח תשלומים ויומן רק למנהלים.

## איך זה בנוי
- `api/` – Cloudflare Worker + Durable Object אחד (`School`) לכל בית הספר. הנתונים, ההרשאות והבקשות ב-`school.js`,
  ניקוי ובדיקת נתונים ב-`model.js`. סיסמת המנהל ב-PBKDF2; מהקישורים של המורים נשמר רק hash.
  השרת מקבל בקשות רק מכתובות האפליקציה (`ALLOWED_ORIGINS` ב-`wrangler.toml`).
- האפליקציה שואלת את השרת כל 20 שניות "מה חדש?" (עם מספר גרסה – אם לא השתנה כלום התשובה קצרה), וגם כשחוזרים אליה.
- `web/` – React + Vite + Tailwind. מסכים ב-`src/components`, חישובי תאריכים/התנגשויות/תשלומים ב-`src/lib/schedule.js`.
  הלוגו (`public/logo.png`) והאייקונים נחתכו מהלוגו שנשלח.

## עמוד נחיתה (`landing/`)
עמוד הצגה של המוצר בשם **"המערכת"** → https://hamaarechet-music.pages.dev. HTML אחד בלי בנייה (`landing/index.html`),
צילומי מסך עם נתוני דוגמה ב-`landing/img` (צולמו מהאפליקציה עם שרת מקומי). מצב לילה לפי המכשיר.
בינתיים בלי פרטי קשר (רק להצגת המוצר). כשיהיה מספר – להוסיף כפתור וואטסאפ בסוף העמוד (`#contact`).

## עלייה לאוויר
`.github/workflows/rock-city.yml` – אחרי מיזוג ל-main (בודק ובונה גם ב-PR). משתמש בסודות הקיימים
`CLOUDFLARE_API_TOKEN` ו-`CLOUDFLARE_ACCOUNT_ID`. אם Cloudflare נותן לאתר כתובת עם סיומת (למשל `rock-city-school-abc.pages.dev`),
השרת כבר מאשר אותה – רק לעדכן את הכתובת כאן.

## בדיקה
- `cd rock_city/api && npm test` · `cd rock_city/web && npm test && npm run build`
- בדפדפן: לבנות עם `VITE_API_URL=http://localhost:8787` ולהריץ את ה-Worker מקומית (`npx wrangler dev`), או שרת node קטן
  שמריץ את `worker.js` עם אחסון בזיכרון.
