# סדר · משימות

אפליקציית ווב (מותקנת כאפליקציה בטלפון: "הוספה למסך הבית") לניהול משימות, זמן ומחשבות לפי תחומי חיים.

כתובת: **https://seder-tasks.pages.dev** (Cloudflare Pages, `.github/workflows/seder.yml`).

## מה יש

- **לוח (דשבורד)** – התקדמות היום, כמה משימות לביצוע יש כרגע (`openTotal`), באיחור, מעקבים, לבדוק, מה בוצע השבוע,
  השבוע הקרוב, משימות חשובות ו"מחכה לתשובה". התחומים לא מופיעים בלוח – יש להם כפתור משלהם.
  בראש הלוח ברכה לפי השעה, עם השם שנכתב בהגדרות ("השם שלי").
- **משימות ותתי משימות** – לכל אחת דד ליין, שעה, רמת חשיבות (גבוהה / בינונית / נמוכה), תזכורת, קישורים והערות.
  את השעה (וגם שעת התזכורת) מקלידים בספרות – "1030" הופך ל-10:30 – במקום השעון העגול (`TimeInput` ב-`components/ui.jsx`).
- **אנשים / גורמים לבירור** – בכל משימה: שם וטלפון (רשות) של מי שצריך לברר מולו, עם כפתור חיוג.
  שמות שכבר נכתבו מוצעים שוב (עם הטלפון), מופיעים בכרטיס המשימה, בחיפוש, בשיתוף ובתיאור ביומן.
- **תמונות וקבצים** – בכל משימה: "תמונה" (מהגלריה או מהמצלמה) או "קובץ" (PDF, מסמך...), עד 4MB לקובץ.
  תמונה גדולה מוקטנת במכשיר לפני ההעלאה. הקבצים נשמרים בשרת (`seder/api/files.js`) ובמשימה רק הפרטים,
  כך שהם מופיעים בכל המכשירים; קובץ שכבר נפתח נשמר גם במכשיר (Cache Storage). צריך חיבור לסנכרון כדי לצרף.
  קובץ שהוסר מכל המשימות נמחק מהשרת אחרי יום. הגיבוי לקובץ כולל רק את הפרטים, לא את הקבצים עצמם.
- **4 סוגים**: משימה ✅, אירוע 📅, מעקב / מחכה לתשובה ⏳, לבדוק בהמשך 💡 (קישורים, סרטונים, המלצות, מחשבות).
- **משימה / תזכורת חוזרת** – בעורך המשימה, "חוזר": כל יום / כל שבוע / כל חודש (`repeat` במשימה). התזכורת יוצאת בכל פעם
  (גם מהשרת – `reminderTimes` ב-`api/reminders.js`), וסימון ✓ מעביר את המשימה לפעם הבאה ומאפס את תתי המשימות.
  ביומן היא נכנסת כאירוע חוזר (RRULE).
- **תחומי חיים** – טיפוח אישי, סידור בית, עבודה, סידורים, ילדים, גיא, ואפשר להוסיף/לערוך/למחוק (שם, סמל, צבע).
  מחיקה: כפתור הפח בראש התחום – בוחרים אם המשימות נשארות (בלי תחום) או נמחקות יחד איתו.
- **רשימות** – תחום מסוג "רשימה" (`kind: 'list'`): מה לארוז, קניות, תווי קניה וזיכויים. מוסיפים פריטים (אפשר להדביק כמה שורות),
  מסמנים, "הכול מחדש" (מוריד את כל הסימונים) ו"ניקוי" (מוציא את מה שסומן). הפריטים הם משימות רגילות בתוך התחום.
  "שינוי סדר" במסך התחומים: מושכים תחום באצבע (בידית ⋮⋮, במחשב גוררים את השורה); הסדר (`order` בכל תחום) משמש בכל האפליקציה ומסתנכרן.
  גם בתוך תחום יש "שינוי סדר" למשימות (פתוחות / לבדוק), באותה משיכה (`order` במשימה, `sortManual`).
  משימות חדשות או שעברו מתחום אחר מופיעות למעלה, שבוצעו – בסוף. הרכיב המשותף: `Sortable` ב-`components/ui.jsx`.
- **תצוגה יומית** – רצועת ימים, ולכל יום שורת "משימה מהירה". אפשר לכתוב טבעי:
  `להתקשר לרופא מחר ב10:00 !` → מחר, 10:00, חשיבות גבוהה (`!` או "דחוף"/"חשוב").
- **ווטסאפ → אפליקציה** – מדביקים הודעה (או "שיתוף" מווטסאפ לאפליקציה באנדרואיד) והיא מזוהה לבד:
  כותרת (מהשורה המודגשת), תאריך ("מחר", "ביום שלישי", "12/10"), שעה ("ב20:00"), קישורים.
  יש מועד → אירוע עם תזכורת חצי שעה לפני; רק קישור → "לבדוק בהמשך".
- **אפליקציה → ווטסאפ** – שיתוף משימה (עם תתי המשימות), יום שלם או תחום, לבקשת עזרה.
- **יומן** – בכל משימה: "ליומן גוגל" או קובץ ‎.ics‎ (אייפון/אאוטלוק) עם התזכורת. בהגדרות: כל הקרובות בבת אחת.
- **תזכורות** – לכל משימה: 9:00 בבוקר, כמה דקות לפני, או "בשעה שאבחר". אחרי "הפעלת התראות" בהגדרות (פעם אחת בכל
  מכשיר) **השרת שולח התראה לטלפון בזמן, גם כשהאפליקציה סגורה** (Web Push). באייפון – רק כשהאפליקציה הותקנה במסך הבית.
- **מצב לילה** – כפתור ירח/שמש בכותרת (במחשב: בתפריט הצד), ובהגדרות: אוטומטי (לפי הטלפון/המחשב) / יום / לילה.
  נשמר בכל מכשיר בנפרד. הצבעים מוחלפים במקום אחד – `src/index.css` (`.dark`); לרקעים משתמשים ב-`bg-card` / `bg-page` ולא ב-`bg-white`.
- **גודל הטקסט** – בהגדרות: רגיל / גדול / גדול מאוד. נשמר בכל מכשיר בנפרד (`src/lib/fontsize.js`, המשתנה `--font-scale` ב-`index.css`).
- **חיפוש** בכותרות, הערות, קישורים ושמות קבצים. **גיבוי/שחזור** לקובץ. עובדת גם בלי אינטרנט.
- **סנכרון בין מכשירים** – טלפון ומחשב רואים את אותן משימות (ראו למטה).

## איפה הנתונים

כל מכשיר שומר עותק אצלו (localStorage), כך שהאפליקציה נפתחת ועובדת גם בלי אינטרנט.
**סיסמה נדרשת רק אחרי יותר מ-10 דקות בלי שימוש** (בטלפון ובמחשב, גם אם האפליקציה נסגרה ונפתחה שוב – הזמן של השימוש האחרון נשמר במכשיר, `seder_active`); בהגדרות יש "נעילה עכשיו".
עם רשת הסיסמה נבדקת בשרת. בלי רשת – מול טביעה מוצפנת (PBKDF2) שנשמרה במכשיר בכניסה האחרונה,
כך שאפשר להיכנס גם בלי אינטרנט (הכניסה הראשונה בכל מכשיר צריכה אינטרנט).

המשימות והתחומים נשמרים גם בשרת (`seder/api`, Cloudflare Worker
"seder-api" עם Durable Object), ומסתנכרנים: בפתיחה, כשחוזרים לאפליקציה, כשהרשת חוזרת, פעם בדקה,
ושנייה וחצי אחרי כל שינוי. סמל הענן בכותרת מראה את המצב.

- כל רשומה נושאת זמן עריכה; כשאותה משימה נערכה בשני מכשירים – העריכה המאוחרת גוברת.
- מחיקה עוברת לכל המכשירים. מה שהיה במכשיר לפני החיבור עולה ומתמזג.
- 10 סיסמאות שגויות ברצף נועלות את הכניסה לרבע שעה. החלפת הסיסמה מנתקת את כל המכשירים.

## התראות (Web Push)

- `seder/api/push.js` – הצפנה (RFC 8291) וחתימת VAPID (RFC 8292) ב-WebCrypto, בלי ספריות. המפתחות נוצרים בשרת פעם אחת
  ונשמרים בכספת – אין סוד להגדיר.
- `seder/api/reminders.js` – מתי יוצאת כל תזכורת (אותו כלל כמו באפליקציה), לפי אזור הזמן של המכשיר (שעון ישראל, כולל שעון קיץ).
- הכספת (`vault.js`) שומרת את המכשירים שנרשמו, ואחרי כל שינוי במשימות קובעת Durable Object alarm לתזכורת הקרובה.
  ב-alarm היא שולחת את ההתראה לכל המכשירים, ומסמנת שנשלחה (שינוי שעה = תזכורת חדשה). מכשיר שביטל נמחק לבד.
- כשהמכשיר מקבל התראות מהשרת, האפליקציה לא מציגה את אותה תזכורת פעמיים.

## אפליקציה לאדם נוסף (קישור)

בהגדרות ← **"אפליקציה לאדם נוסף"** (רק באפליקציה הראשית) כותבים שם ולוחצים "יצירת קישור", ושולחים אותו (ווטסאפ / העתקה).
הקישור נראה כך: `https://seder-tasks.pages.dev/?u=<מזהה>`. מי שפותח אותו בוחר סיסמה (בפעם הראשונה) ומקבל אפליקציה ריקה משלו:
משימות, תחומים, קבצים ותזכורות נפרדים לגמרי. הוא לא רואה את המשימות של האפליקציה הראשית, וגם הבעלים לא רואה את שלו.
- בשרת: כל אדם הוא כספת נפרדת (`space:<מזהה>`) עם הסיסמה שלו (`seder/api/spaces.js`). הרשימה נשמרת בכספת הראשית (`registry`).
- במכשיר: המזהה נשמר (`seder_space`), כך שפתיחה מהמסך הראשי או מהתראה נכנסת לאותו מרחב. הנתונים במכשיר נשמרים
  במפתחות נפרדים (`seder_v1@<מזהה>` וכו', `src/lib/space.js`). באפליקציה הראשית המפתחות לא השתנו.
- לאדם נוסף אין "בקשה לשינוי באפליקציה", יתרת קרדיטים או ניהול קישורים. בהגדרות יש לו "יציאה במכשיר הזה".
- במסך הקישורים: "איפוס סיסמה" (כל המכשירים שלו מתנתקים, ובפתיחה הבאה של הקישור בוחרים סיסמה חדשה; המשימות נשארות)
  ו"מחיקה" (כל הנתונים שלו נמחקים והקישור מפסיק לעבוד). עד 30 קישורים.
- מי שפותח את הקישור ראשון בוחר את הסיסמה – לכן שולחים אותו רק לאדם עצמו.

## בקשות לשינוי מתוך האפליקציה

בהגדרות (ובמחשב גם בתפריט הצד) יש **"בקשה לשינוי באפליקציה"**: כותבים מה לשנות ושולחים.
1. השרת פותח issue במאגר עם התווית `seder-request`.
2. **הערכת מחיר לפני הביצוע:** `.github/workflows/seder-requests.yml` (job `estimate`) שואל את Haiku מה גודל השינוי
   (קטן / בינוני / גדול, כסנט), והמחיר נקבע לפי מה ששינויים באותו גודל עלו בפועל (`seder/api/costs.js`, `request-costs.mjs`).
   באפליקציה מופיע "השינוי יעלה בערך $X" עם "לבצע" (התווית `seder-go`) או "לבטל" (הבקשה נסגרת בלי עלות נוספת).
3. אחרי "לבצע" (job `work`) Claude מבצע את הבקשה, הבדיקות רצות, ונפתח PR לאישור
   (ענף `seder/request-<מספר>`). רק issues שנפתחו בשם בעל/ת המאגר מופעלים.
4. **האישור נעשה מתוך האפליקציה, בלי GitHub:** בבקשה שמוכנה מופיע ההסבר של Claude (מה השתנה ומה לבדוק)
   עם הכפתורים "לאשר ולהעלות" (השרת ממזג את ה-PR, הבקשה נסגרת, והשינוי עולה תוך כדקה) ו"לא מתאים"
   (ה-PR והבקשה נסגרים בלי שינוי). בקשה שנכשלה: "לנסות שוב" (מוסיף את התווית `seder-retry`).

באפליקציה רואים לכל בקשה את המצב: התקבלה / מעריך מחיר / מחכה לאישור שלך / בעבודה / מוכן לאישור / בוצע / לא הצליח / נסגרה,
וכמה היא עלתה בפועל. ההערכה והעלויות נשמרות כהערות נסתרות בסוף ה-issue (`<!-- seder-estimate ... -->`, `<!-- seder-cost ... -->`).

**היתרה בחשבון הקרדיטים** מוצגת בראש המסך. Anthropic לא מאפשרת לקרוא אותה, ולכן מקלידים אותה ("עדכון")
מ-console.anthropic.com → Billing – פעם אחת וכל פעם שמטעינים. השרת שומר אותה (`/credits`, בכספת) ומוריד ממנה
את כל העלויות שנרשמו מאז.
השרת מאשר רק PR מהענף `seder/request-<מספר>` של בקשה שנפתחה מהאפליקציה – לא PR אחר במאגר.

### הגדרה (פעם אחת)

צריך מפתח גישה אישי של GitHub (fine-grained), **מהחשבון שהוא בעל המאגר**:
GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token
- Repository access: רק `red-grass`
- Permissions: **Contents** – Read and write, **Issues** – Read and write, **Pull requests** – Read and write

שומרים אותו כסוד במאגר בשם `SEDER_GITHUB_TOKEN`, ומריצים Actions → seder → Run workflow (כדי שהשרת יקבל אותו).
העבודה של Claude משתמשת בסוד הקיים `ANTHROPIC_API_KEY` (עולה כסף לפי שימוש).
